# Prisma TypeScript Type Errors - Fix Guide

## Problem Summary

CI type-check is failing with **664 TypeScript errors** due to mismatches between code and generated Prisma client types.

## Root Cause

The Prisma schema uses **PascalCase model names** as relation field names, but code is using lowercase field names that don't exist in the generated types.

### Prisma Schema Example (from `schema.prisma`)
```prisma
model Booking {
  customerId String?
  driverId   String?
  
  // Relations use PascalCase model names as field names
  User       User?    @relation(fields: [customerId], references: [id])
  Driver     Driver?  @relation(fields: [driverId], references: [id])
  Assignment Assignment[]
  BookingItem BookingItem[]
}
```

### Generated Prisma Types
```typescript
export type BookingInclude = {
  User?: boolean    // NOT "customer"
  Driver?: boolean  // NOT "driver"
  Assignment?: boolean
  BookingItem?: boolean
  Drop?: boolean    // NOT "drops"
  // ... etc
}
```

## Error Categories & Fixes

### 1. Include/Select Errors (~200 errors)

**Problem**: Code uses lowercase field names that don't exist
```typescript
// ❌ WRONG
include: {
  driver: true,      // Error: Property 'driver' does not exist
  customer: true,     // Error: Property 'customer' does not exist
  drops: true,        // Error: Property 'drops' does not exist
}
```

**Solution**: Use PascalCase model names
```typescript
// ✅ CORRECT
include: {
  Driver: true,      // Relation to Driver model
  User: true,        // Relation to User model (customer)
  Drop: true,        // Array of Drop models
}
```

### 2. Property Access Errors (~300 errors)

**Problem**: After including relations, code accesses with wrong names
```typescript
// ❌ WRONG
const booking = await prisma.booking.findFirst({
  include: { Driver: true }
});

console.log(booking.driver.name);  // Error: Property 'driver' does not exist
```

**Solution**: Access with PascalCase names matching include
```typescript
// ✅ CORRECT  
const booking = await prisma.booking.findFirst({
  include: { Driver: true }
});

console.log(booking.Driver.name);  // Correct: matches include key
```

### 3. CreateInput Errors (~150 errors)

**Problem**: Objects passed to `.create()` missing auto-generated fields
```typescript
// ❌ WRONG
await prisma.auditLog.create({
  data: {
    actorId: 'user-123',
    action: 'update',
    targetType: 'booking',
    // Missing: id, updatedAt (auto-generated by Prisma)
  }
});
```

**Solution**: Remove explicit type annotations, or use `UncheckedCreateInput`
```typescript
// ✅ CORRECT - Let Prisma infer the type
await prisma.auditLog.create({
  data: {
    actorId: 'user-123',
    action: 'update',
    targetType: 'booking',
    // Prisma will auto-generate id and updatedAt
  }
});

// OR use Unchecked variant
const data: Prisma.AuditLogUncheckedCreateInput = {
  actorId: 'user-123',
  action: 'update',
  targetType: 'booking',
};
await prisma.auditLog.create({ data });
```

## Common Replacements Needed

| Wrong (Code) | Correct (Prisma) | Context |
|--------------|------------------|---------|
| `driver` | `Driver` | Booking relation to Driver |
| `customer` | `User` | Booking relation to User |
| `drops` | `Drop` | Route array of Drops |
| `pickupAddress` | *Remove from include* | Use ID field or complex name |
| `dropoffAddress` | *Remove from include* | Use ID field or complex name |
